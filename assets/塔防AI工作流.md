# **塔防AI工作流****一、愿景**

我想做一款流程稍微简单的用来做试玩广告的小游戏，以此来验证一个玩法。

# **二、游戏整体设计**

1.  引擎CocosCreator3.8.8,脚本TypeScript.
2.  坐标钳制:因为是伪3D，限制在XY平面坐标限制在XY轴
3.  游戏美术风格与透视效果：2d像素风格，场景存在透视效果

游戏主玩法流程设计：

- 1.  **游戏开局初始状态** 玩家出生在木篱笆围成的小城内，城内预先布置生肉摊位、金币存放地块、箭塔建造交互地块；玩家获得初始资源。弹出新手引导，提示滑动操控角色。城外持续刷新怪物，怪物向防御工事移动并发起攻击。
    2.  **第一阶段引导：建造箭塔** 玩家完成首次移动操作后，生肉摊位开始周期性刷新顾客。跟随指引前往箭塔建造地块，完成箭塔建造。 箭塔建造完成后，场景解锁：生肉摊位东侧帮手购买交互 UI；城门具备自动开关规则，玩家可移动至城外区域。（注意：英雄购买 UI **不在**本阶段开放。）
    3.  **战斗与生肉交易循环引导** 玩家在野外可近战击杀怪物，怪物被击杀后掉落肉块；玩家拾取肉块后，跟随引导前往生肉摊位交互区域交付肉块。 摊位存在顾客排队机制，顾客提出物资需求，交付对应物资后产出金币并放置在金币地块；玩家靠近金币地块即可拾取金币。
    4.  **第二阶段引导：解锁摊位帮手** 玩家金币达到指定条件，触发购买帮手引导。成功购买帮手后，帮手常驻摊位自动完成物资交付交易，不再需要玩家亲自站在摊位交互区。
    5.  **第三阶段引导：解锁英雄单位** **仅在帮手购买成功后**，两座箭塔旁开放英雄购买交互 UI。跟随指引购买英雄，购买时提供二选一选择；购买完成后，原交互点位转化为专用储肉地块。英雄击杀怪物产出的肉块自动存入该地块，摊位帮手可主动前往储肉地块取肉、运回摊位持续交易。

规则约束：单个摊位绑定专属储肉地块。

- 1.  **第四阶段引导：解锁烤肉摊位** **任意一名英雄解锁后**，开放新摊位购买权限。购买后显示预埋的烤肉摊位并附带专属帮手；若摊位占了原围墙位置，购买时隐藏 `replaceWalls` 占位墙。生肉在摊位内经过加工转化为烤肉，用于交易。
    2.  **第五阶段引导：区域拓展与木头产业链** 烤肉摊位解锁完成后，场景东西两侧解锁地块拓展交互 UI，两侧拓展区域内容对称。 购买拓展地块后开启新区域，区域内生成森林、伐木工购买 UI、新增箭塔建造点位、木头交易摊位（自带帮手）。玩家进入森林可采集木材，木材拥有完整拾取、交付、顾客交易循环。
    3.  **游戏**结束**条件** 成功建造东侧、西侧拓展区域内任意一座箭塔，本局游戏流程结束。

游戏系统设计

### 1\. 玩家控制系统

**包含内容**

- 虚拟摇杆输入处理、角色移动、移动限制规则
- 玩家角色状态管理：地面状态 / 箭塔搭载状态切换
- 玩家角色基础交互判定（拾取资源、登上箭塔等交互请求） **禁止实现** 战斗伤害判定、资源实体转移、摊位逻辑 **对外交互**
- 向防守战斗系统同步玩家位置、当前状态（地面 / 箭塔）
- 向资源经济系统发起【拾取资源】请求

### 2\. 防守战斗系统

**包含内容**

- 怪物生成、怪物寻路 AI、怪物攻击城墙逻辑、城墙血量管理
- 玩家战斗判定：地面斧子攻击、箭塔远程射击
- 箭塔英雄、英雄技能 CD、大范围攻击逻辑
- 击杀判定、战斗伤害逻辑 **禁止实现** 资源实体生成、金币结算、NPC 行为控制 **对外交互** 怪物被击杀后，向外抛出【怪物死亡事件】； 资源经济系统监听该事件，生成掉落肉片资源实体。

### 3\. 资源经济系统

**包含内容**

- 所有资源实体：生肉、烤肉、木头的生成、销毁、容量上限管理
- 资源拾取、资源飞行动画、资源转移逻辑
- 摊位体系：生肉摊位、烤肉摊位（生肉静置转化烤肉）、木头摊位
- 顾客刷新、顾客需求校验、资源消耗、金币产出结算 **禁止实现** NPC 寻路、NPC 自主采集逻辑；不直接控制任何 NPC **对外交互**
- 接收玩家控制系统、NPC AI 系统发来的【资源拾取 / 交付】请求
- 金币数值变更事件推送至商店系统

### 4\. NPC AI 系统

**包含内容**

- 帮手、伐木工两类 NPC 单位生命周期管理
- NPC 寻路、目标选择逻辑：伐木工砍伐树木；帮手搬运资源、运送至摊位
- NPC 空闲 / 工作状态切换 **禁止实现** 资源实体移动、摊位库存修改；AI 只发起请求，不直接改动资源 **对外交互** 向资源经济系统发送【拾取资源】【交付资源至摊位】指令

### 5\. 商店系统（不是真正的商店）

**包含内容**

- 商店 UI 展示、商品配置表读取
- 金币扣除校验、购买前置条件校验 **禁止实现** 创建英雄、生成 NPC、解锁地块、生成摊位；商店只做 “交易校验” **对外交互** 购买成功后，发送创建 / 解锁指令至对应系统：
- 购买英雄 → 防守战斗系统
- 购买帮手 / 伐木工 → NPC AI 系统
- 购买摊位 → 资源经济系统
- 购买扩展地块 → 场景地块管理系统

### 6\. 场景地块管理系统

**包含内容**

- 地块解锁状态、地块占用校验
- 场景可放置区域管理、树木实体管理（树木刷新、被砍伐状态） **禁止实现** 资源产出、NPC 控制 **对外交互**
- 伐木工砍伐树木事件由场景地块系统通知资源经济系统生成木头
- 商店系统收到地块购买指令后，修改地块解锁状态

游戏数值设计

全局约定：资源实体模型 ≠ 结算金币，区分【表现模型数量】与【经济结算数值】

1.  绑定规则：**1 个摊位 仅对应 1 块专属储肉地块**
2.  帮手行为：无搬运数量上限（可后续扩展配置上限）
3.  烤肉转化：1 生肉 → 1 烤肉（转化时长可配置，本表只预留参数位）

## 五、新手引导触发阈值

1.  玩家拥有金币≥60：触发【购买摊位帮手】引导

## 六、顾客交易相关预留数值（配置表项）

1.  顾客单次需求资源数量：随机区间（策划后续配置区间，例如 2~5 单位资源）
2.  顾客排队最大数量：预留配置项
3.  顾客交付物资后离场动画时长：预留配置项

## 七、战斗相关基础常量

1.  玩家近战攻击：单体怪物一击击杀
2.  英雄攻击：怪物一击击杀
3.  城墙：存在血量配置项；血量归零无失败惩罚，仅血条表现变化
4.  生肉掉落规则：怪物死亡生成 1 份生肉；英雄击杀→自动存入绑定储肉地块；玩家击杀→肉块落地等待拾取

## 游戏UI设计

屏幕右上角是肉块与金币的UI，包括图标，背景和数值显示

屏幕右下角是固定的摇杆移动提示，当玩家超过3s没有移动摇杆，显示这个UI，并伴随一个虚拟遥感UI动画，在玩家鼠标点击后消失，显示带有逻辑的常规的摇杆UI

以下UI对象的根节点都是实体对象：城墙，玩家的血条，英雄的技能cd，顾客的需求，具体描述如下：

城墙，玩家的血条：水平填充，分背景和绿条俩个node，会给美术素材

英雄技能cd：360度绿色圆形填充，填充满时，倒计时结束，之后从零开始循环

顾客需求：白色气泡背景，竖直绿色填充，气泡底部显示需求数量，中间显示需要的生肉，

给一块肉，物品图标做呼吸抖动，数值减一；达成后（数值变为0）数字和物品消失，变成打钩图标标识，表示交易完成

英雄二选一：整体最底层有个透明度40%的黑色遮罩，屏幕中间，俩个方形的背景，中间是可供选择的英雄，在点击后会有一个放大+淡出的效果

触发区域UI:由背景图片，金币图标，所需消耗金币的数目构成，做成一个预制体，显示上做区别

## 游戏动画设计

虚拟遥感UI动画：手指在遥感背景内做划倒8的动画，遥感的跟跟随手指运动。

怪物：移动前进动画，死亡动画，攻击动画

城墙动画：受到怪物攻击的时候，会有闪烁成全白色的动画

门动画：玩家靠近一定距离后会开门，离开会关上

玩家主角动画：idle动画，移动前进动画，射箭攻击动画，近战攻击动画，砍树动画，玩家从地面跳跃到箭塔的位移动画

道具动画：道具被采集时，从放置点到目的地都是以先飞到高于目的地一定距离的高度，在落到目的地，这种有点抛物线的感觉

其他角色动画：帮手、顾客的idle和移动前进动画，伐木工砍伐动画。每个英雄的普通远程攻击动画，远程攻击发射出去的光波的向目标飞去的移动动画，英雄释放大范围技能动画，技能特效动画

# 代码规范设计

1.  引擎官方API链接： https://docs.cocos.com/creator/3.8/api/zh/。所有 API 请参考这个文档。
2.  避免类间的循环引用
3.  为脚本中为每个字段补充tooltip，简要告知字段作用，为需要引用其他节点的字段，补充tooltip提示该字段需要引用什么节点
4.  功能不单一的游戏对象，渲染组件尽量位于子物体中
5.  目录结构：

- assets/scenes/ 存放场景文件
- assets/scripts/ 存放脚本
- assets/resources/prefabs/ 存放预制体
- assets/resources/sprite/存放美术资源
- assets/resources/sprite/frames/存放序列帧

1.  预制体对象：顾客，肉，金币，3个英雄，功能购买UI，站位交互触发区域（美术资源可选显示），怪物，3种英雄技能实体，3种英雄普攻的光波，箭
2.  动画对象：
    1.  序列帧动画：各角色对应行动动画，如玩家，怪物，其他角色，英雄技能特效
    2.  位移动画：各个道具动画，玩家跳上箭塔的动画，玩家或英雄的普攻的射出的箭和光波，虚拟遥感UI动画
    3.  程序动画：城墙动画
3.  碰撞器对象：受怪物攻击的城门城墙。玩家，怪物
4.  触发器对象：需要金币去购买功能的UI。触发玩家跳上箭塔，放置资源道具与采集资源道具的站位触发区域（美术资源可选显示）。怪物。怪物死亡掉落的肉。经砍伐得到木头的树。
5.  资源命名：约定前缀或后缀，如 pref_ 开头为预制体，atlas_ 开头为图集，snd_ 开头为音效。
6.  代码命名规定：类名：大驼峰；变量/函数名：小驼峰；私有变量：以下划线开头；枚举：大驼峰。
7.  单例模式使用标准的单例实现模板
8.  事件通信：强制推荐使用 EventTarget 或自定义事件系统进行跨组件通信，避免组件间直接耦合调用。
9.  动态资源的加载方式，使用 resources.load
10. 单次动画，用 Animation.EventType.FINISHED 监听结束
11. 一些可配置参数尽量暴露出来，比如位置之类的,偏移之类的
12. 游戏是XY平面，又需要有透视效果，游戏需要给美术资源渲染节点增加设置层级SortingOrder2D的脚本组件，sortingOder属性值以渲染节点的世界坐标的y的相反数为准。当存在道具飞到角色身上的情况，已经飞到身上的道具的层级要小于角色层级。

# **模块设计**

敌人模块：

作用：成群的敌人攻击城墙，向玩家靠近，给玩家模块发展欲望和发展后屠戮的爽感

规则：在玩家模块第一次移动后开始在屏幕外坐标刷新，并朝着玩家移动，被围墙阻挡时会攻击它；敌人会被任何攻击一击秒杀，死亡时掉肉

边界：敌人同时在场数量限制在30人以内，敌人之间不能穿模

英雄模块：

作用：协助玩家攻击敌人，同时协助玩家采集肉资源

规则：英雄刚开始实例化时是普攻的状态，技能CD状态，先是间隔时间释放普通远程技能单体攻击，在大范围技能CD值达到后，释放大范围攻击技能。

英雄一共有4个：

普攻都是发射出光波随机击中较近的怪物。命中怪物后开启下一轮攻击。

每种英雄的CD后的范围攻击技能都是从某个较近距离点开始，延迟较短时间，向范围最远处，实例化相应技能特效预制体播放帧序列动画，动画结束秒杀这个位置范围内的怪物。

区别是，前两种个英雄是地面冒出冰柱，风暴技能，另外两种是从天而降的雷电、火箭技能，他们的代码实现上可能存在层级与实例化的y值上的区别。生成位置是范围内形成的矩形框，一行有这几个，存在几行，支持配置。技能全部释放完动画也播完，英雄开始进入普攻状态并等待CD冷却时间。

玩家模块：

规则：玩家通过鼠标操作摇杆移动，因为是物理世界，所以使用rigidbody进行移动

玩家走到到城墙外，一定范围内存在怪物即采取范围攻击，范围较小并且支持配置。玩家在箭塔上，变成拿着弓箭攻击的状态。选择最近的怪物攻击。当弓箭命中怪物后开始下一次射箭攻击。箭以固定时间命中怪物。

肉和金币，木头都会有背在玩家背上的状态，它们都有一个root节点来标识从哪里开始，

资源道具从右向左按金币，肉，木材的顺序有间距的排列。采集到同种资源道具，向上堆积，间隔堆积距离支持配置。显示上，堆积到10个后，采集数继续增加但是显示上道具不再增加。

摊位模块：

规则： 玩家进入触发区域，做出相应行为

摊位前的交互区：玩家在触发区内，可以上交对应资源，没有帮手的时候，需要玩家在触发区内出售给顾客。

一共有烤肉摊位，生肉放置摊位，木头销售摊位，同样有一个root代表资源放置位置（生肉摊位有俩个）

触发区有帮手或玩家，且摊位有资源时，将资源飞到顾客身上代表一次交易

烤肉的摊位左边是烤的占位点，肉先飞到这个展位点一定时间变成烤肉再飞到右边烤肉的放置占位点。

放置点模块：

一共分为生肉放置点，木头放置点，金币放置点；

金币有4个放置的占位点，木头是4个放置点，生肉则是6个放置点

可以被玩家或者帮手拾取

帮手模块：

规则：帮手可以携带肉，木材资源；初始化站立在摊位前的交互区，当摊位有资源时与顾客进行交互，没有资源时，去对应的放置资源点拾取，都没有资源则不交互

顾客模块：

作用：产出金币资源

一开始一个摊位前间距排列10个顾客，队列首个的顾客才显示需求展示UI。需要的资源数目随机但不超过10。出售给顾客的需求达到后，顾客向反方向离开，后方顾客前移动，移动完后在队尾生成顾客。

扩展区的伐木模块：

有一个伐木工， 协助玩家砍伐木头。没有采集到身上的功能。

伐木工或玩家进入则开始砍伐并掉落木头到。一棵树每砍一次掉落一个木头，总共砍5次消失。砍伐时有颜色动画。场景总共有6颗数，玩家或伐木工随机砍倒两颗，在原位置上重新生成数
